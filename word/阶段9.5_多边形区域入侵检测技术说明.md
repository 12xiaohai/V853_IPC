## 1. 本阶段范围与状态

在现有NPU实时人形检测、LCD/RTSP/MP4画框及越线检测之外，新增区域入侵规则。
本阶段代码已接入主程序，主机回归测试和ARM目标语法检查通过；V853实景测试待完成。
阶段9.4已观察到双向越线事件及正常退出，但真实动作对应、边界防抖、冷却仍保留专项验收项。

当前区域事件只输出日志和调用可选回调，不会播放声音，也不绘制区域边界。

## 2. 文件与数据通路

| 文件 | 作用 |
| --- | --- |
| `sample/ipc_camera/include/region_intrusion.h` | 区域顶点、配置、事件和生命周期接口 |
| `sample/ipc_camera/app/region_intrusion.c` | 几何、轨迹关联、状态机、工作线程 |
| `sample/ipc_camera/app/main.c` | 默认区域配置、启动和反向清理 |
| `tests/region_intrusion_test.c` | 不依赖板端的算法与线程回归测试 |
| `tests/stubs/utils/plat_log.h` | 仅供主机测试使用的日志替身 |

工作链路：

```text
VIPP 8 -> NPU -> NpuDetectionSnapshot（互斥锁内复制）
                  |-- 越线线程
                  |-- ORL画框线程
                  `-- 区域线程 -> 单目标区域状态 -> enter/leave日志及回调
```

区域线程不调用GetFrame/ReleaseFrame，不再申请VIPP，不持有视频帧指针。
它每50 ms取一次快照，只处理新的非零sequence，不把同一结果重复算作两帧。
Makefile递归扫描sample下的.c文件，因此新模块自动参加编译，无需增加链接库。
tests位于sample外，不会被产品构建扫描。

## 3. 默认区域与坐标

main中配置region_id=1，使用320x320模型画面的右半边：

```text
顶点0：(160, 0)
顶点1：(320, 0)
顶点2：(320, 320)
顶点3：(160, 320)
```

这表示x>=160的区域，包含多边形边界。在当前直接拉伸缩放的1920x1080编码画面中，
对应右半边x>=960；不能直接拿旋转后的480x800 LCD坐标配置区域。
LCD画面经过G2D旋转，验证左右时建议先以RTSP编码画面及日志模型坐标为准。

目标判定点与越线一致，取person检测框底边中心：

```text
point_x = (xmin + xmax) / 2
point_y = ymax
```

这是落脚位置的近似点。人只露上半身时，框底边并不是真正脚底，规则只能判断该近似点。
修改区域时，在main中设置3～8个顺序排列的顶点，不重复首点。
支持凸/凹简单多边形，顺时针或逆时针均可；拒绝越界、重复点、共线拐点、零面积、自交。
一个上下文监控一个多边形，当前仅启动一个区域实例，不声称已实现多区域配置界面。

## 4. 与原项目的关系

原项目的`sample/common/aiservice_detect.c`中有`pnpoly()`射线法，
并在`CROSS_WORK_MODE_RECT`分支对四顶点区域判断进入/离开。
本模块沿用“目标点 -> 多边形内外 -> 状态变化”的基本思路，不是原代码逐行复制。

当前变化包括：

- 原项目使用检测框中心队列；本模块读取NPU快照并使用底边中点。
- 原项目每个区域共用状态；本模块每条临时轨迹独立维护状态，避免多人互相覆盖。
- 原项目即时根据内外变化触发；本模块增加连续有效快照确认。
- 原pnpoly使用整数除法；本模块用叉积符号判断射线交点，避免除法截断。
- 原项目在规则线程调用声音报警入口；本阶段先保留事件回调，阶段9.6再独立处理播放。

## 5. 点在多边形内的几何判定

从目标点向右发出水平射线，穿过边的次数为奇数表示在内，偶数表示在外。
采用半开区间避免经过顶点时被相邻两条边重复计数。
若点恰好位于有限边段上，直接视为在内。
这也允许ymax=320的裁剪框在覆盖画面底部的区域中参与判定。

几何使用long long叉积，并把模型宽高限制为8192以内；当前实际为320。
多边形必须先通过校验再启动线程。

## 6. 轻量轨迹关联

YOLOv8本身没有人员ID。模块维护有界轨迹表，默认最多16条，接口上限32条。
每个新快照中，从旧轨迹和person点之间选择距离最小的一对，距离不超过96模型像素。
双方各匹配一次；完成旧轨迹关联后才创建新轨迹，避免多个检测框共用一个新ID。

未匹配轨迹每次新快照增加漏检计数，超过5次后删除；短暂漏检保留已确认的在内/在外状态，
但清空待确认计数。漏检不等于离开，不发布leave事件。

区域和越线模块分别维护临时轨迹：即使日志ID数值相同，也不能认为它们是同一个人。
最近距离关联不是身份识别；多人交错、快速移动、框坐标跳变可能造成关联错误或ID切换。
长漏检后重新检测到区域内人员会建立新ID并重新确认enter；阶段9.6的全局声音冷却会处理
播放层重复，但不能把这个局限当成已经解决的永久人员跟踪。

## 7. 区域状态机

| 当前状态 | 新观察 | 后续行为 |
| --- | --- | --- |
| OUTSIDE | 点在内 | ENTER_PENDING，开始连续确认 |
| ENTER_PENDING | 连续3个新快照在内 | INSIDE，发布一次enter |
| ENTER_PENDING | 点在外或漏检 | 撤销确认，回到OUTSIDE |
| INSIDE | 点仍在内 | 保持，不重复enter |
| INSIDE | 点在外 | LEAVE_PENDING，开始离开确认 |
| LEAVE_PENDING | 连续3个新快照在外 | OUTSIDE，发布一次leave |
| LEAVE_PENDING | 点回到区域内 | 撤销离开，回到INSIDE |
| LEAVE_PENDING | 漏检 | 撤销确认，保留INSIDE |

在约10 FPS推理下，3次连续观察通常跨越约200 ms；不是精确固定时长保证。
确认统计的是消费到的相邻sequence，若序号跳跃，待确认计数会清零。
新目标首次就在区域内，也会在3次确认后发布enter：这里表示“确认区域内有人”，
不要求必须先观察到区域外。对已确认的同一轨迹，停留不重复报警。

若500 ms内没有新快照，区域线程清除陈旧轨迹并警告一次，不补发leave；
恢复新快照后重新关联。等待使用CLOCK_MONOTONIC，不受NTP调整系统时间影响。

## 8. 事件接口与日志

事件包含region_id、track_id、enter/leave类型、sequence、VI帧PTS和目标判定点。
示例（仅示意格式，不是本阶段板端验收日志）：

```text
[REGION] Intrusion detector started: region=1, points=4, enter_confirm=3, leave_confirm=3, ...
[REGION] Intrusion event: region=1, id=1, type=enter, point=(200,300), sequence=4, ...
[REGION] Intrusion event: region=1, id=1, type=leave, point=(130,300), sequence=23, ...
[REGION] Detection thread stopped: snapshots=..., enter=..., leave=..., expired=...
```

当前event_callback为空。未来接入报警队列时，只让enter触发入侵声音；leave用于记录状态。
回调在区域线程内运行，不允许同步播放WAV或执行长时间阻塞工作。

## 9. 生命周期与线程安全

main先启动NPU、ORL和越线，再创建并启动区域模块。
正常退出和启动失败共用cleanup入口，先stop/join区域线程，再销毁上下文；
之后停止越线、两个ORL消费者，再停止NPU和媒体模块。
停止标志使用C11原子变量，不用volatile冒充线程同步。

destroy在忘记stop时自动join；join失败不能释放仍可能被线程访问的内存。
可执行stop后再start，新一轮会重置轨迹和累计统计。
区域线程取快照失败会打印错误并退出；当前主线程没有自动重启规则线程的健康监控。

先把本地代码同步到虚拟机，再在仓库根目录执行：

```

# ./sample_strip --npu-model /mnt/UDISK/yolov8n.nb
```

按RTSP画面中的人框底边中心测试，尽量让人体完整出现：

1. 在左半边停留，应没有enter。
2. 进入右半边并保持检测稳定，应有一次type=enter。
3. 在右半边停留5～10秒，同ID不应继续刷enter。
4. 回左半边并保持，应有一次type=leave。
5. 再回右半边，应再次enter。
6. 站在中线附近，检查边界抖动；持续3帧坐标真的越界仍可能确认状态变化。
7. 两人分别进出，检查状态是否独立，同时记录ID切换与漏检。
8. 检查LCD、RTSP、MP4有画面/声音和框，越线日志仍正常。
9. Ctrl+C后应看到REGION停止统计及主程序退出码0。

不要以日志事件数量代替动作记录。保留完整启动、事件、退出日志及当时人员移动说明。

## 12. 常见现象与问题复盘

| 现象 | 解释与检查 |
| --- | --- |
| 没声音或没有区域边界线 | 本阶段未接AO播放，也未新增区域轮廓；不是启动失败 |
| 确认进入失败 | 查persons、底边中点坐标、连续3个sequence、漏检和轨迹匹配 |
| 人一直在区域内却再次enter | 查track_id是否变化、长期漏检、96像素关联超限或500ms快照超时 |
| 没看到人离开却没有leave | 离开视野属于漏检，不是连续观察到区域外，本模块不会虚构leave |
| Point/region配置创建失败 | 顶点越界、排序不正确、自交、重复、共线或参数非法 |
| NPU snapshot stale | 新快照超过500ms不更新，先查NPU线程/VI/NPU推理，不要归因于声音播放 |
| 边界附近仍有重复状态变化 | 时间防抖不是空间滞回；连续3帧在另一侧仍会确认，结合轨迹和实际动作复测 |

此前启动视频PTS警告、一次VI FIFO溢出、ISP/显示驱动提示仍保留为历史待观察项。
本阶段不修改这些媒体路径，不声称其根因已解决；必要时查阶段9.4复测记录和历史问题文档。

### 14.2 为什么没有leave，尚不能判定离开流程通过

当前leave要求同一已确认在内的轨迹连续3个有效新快照位于区域外。
走出摄像头视野、被遮挡或NPU未检测到，只会撤销待确认计数并累计漏检；
超过5次后删除轨迹，不虚构leave。

因此本记录只证明进入事件出口和停止流程可用，不证明：

- 人员实际回到左半边且仍被持续检测时能正确报告leave；
- 同一轨迹在右半边持续停留不会重复enter；
- 完成一次真实离开后，再进入只报告一次；
- 多人同时出现或边界抖动时没有误报。

越线events=0也不能单凭日志归因于规则故障：实际是否跨线、轨迹是否连续、
是否离开滞回带都尚未结合动作记录确认。

复测应让人员始终留在画面内，先左侧停留，再右侧保持5～10秒，
然后左侧保持，再回右侧。以RTSP人框底边中心和模型点坐标判断位置，
不要把身体某一部分位于左边等同于底边中心已经位于区域外。
若检测不稳定，先改善完整人体入镜、光线和姿态，不直接降低确认数掩盖问题。
