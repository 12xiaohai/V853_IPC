- 文档版本：V1.0
- 完成日期：2026-09-30
- 项目目录：`sample_demo`
- 验证平台：V853 开发板、Tina Linux

- 阶段状态：开发板验证通过

## 1 阶段目标

本阶段建立应用程序的最小可运行框架，为后续的视频采集、实时显示、编码、推流、录像和 AI 检测提供统一的初始化与退出流程。

本阶段完成以下功能：

1. 初始化 Allwinner glog 日志系统。
2. 创建和释放应用级上下文 `IpCameraContext`。
3. 配置并初始化 MPP 和 ISP。
4. 获取系统当前 PTS，并建立媒体时间戳基准。
5. 注册 `SIGINT` 和 `SIGTERM` 信号处理函数。
6. 实现持续运行的主循环。
7. 收到退出信号后，按照确定顺序释放全部已初始化资源。

## 3 程序执行流程

```text
main
  -> 初始化 pthread 互斥锁
  -> 注册 SIGINT 和 SIGTERM
  -> 初始化 glog
  -> 创建 IpCameraContext
  -> 初始化应用上下文
  -> 配置并初始化 MPP
  -> 获取当前 PTS
  -> 设置 MPP PTS 基准
  -> 进入主循环
  -> 收到退出信号
  -> 退出 MPP
  -> 销毁 IpCameraContext
  -> 关闭 glog
  -> 销毁 pthread 互斥锁
  -> 返回退出码
```

所有清理操作集中在 `main()` 的 `cleanup` 路径中。程序使用状态变量记录日志系统和 MPP 是否已经初始化，只有成功初始化的资源才执行对应的反初始化操作。

这种结构可以覆盖以下三种退出情况：

- 初始化过程中发生错误。
- 程序正常结束。
- 收到 `SIGINT` 或 `SIGTERM`。

## 4 日志系统

### 4.1 接口

```c
int init_glog(char *argv[]);
void deinit_glog(void);
```

### 4.2 初始化过程

`init_glog()` 在调用任何 `alogd()` 或 MPP 接口之前执行。函数首先创建 `/tmp/log` 目录，然后填充 `GLogConfig` 并调用 `log_init()`。

当前主要配置如下：

| 配置项 | 当前值 | 作用 |
|---|---:|---|
| `FLAGS_logtostderr` | 0 | 启用文件日志 |
| `FLAGS_stderrthreshold` | `INFO` | INFO 及以上日志同时输出到终端 |
| `FLAGS_minloglevel` | `INFO` | 过滤低于 INFO 的日志 |
| `FLAGS_logbufsecs` | 0 | 日志立即刷新 |
| `FLAGS_max_log_size` | 1 | 单个日志文件最大约 1 MB |
| `LogDir` | `/tmp/log` | 日志文件目录 |

`/tmp` 通常属于临时文件系统，设备重启后日志可能消失。该路径适合开发调试，不适合作为长期日志存储目录。

### 4.3 退出过程

程序完成 MPP 和上下文清理后调用：

```c
log_quit();
```

关闭日志之后不能继续调用 `alogd()`、`alogw()` 或 `aloge()`。

## 5 应用上下文生命周期

当前上下文定义为：

```c
typedef struct IpCameraContext {
    int initialized;
} IpCameraContext;
```

当前结构只保存基础初始化状态。后续会逐步加入 VI、VO、VENC、音频、RTSP、录像和 AI 模块所需的配置及运行状态。

### 5.1 创建上下文

```c
IpCameraContext *constructIpCameraContext(void)
{
    IpCameraContext *context = calloc(1, sizeof(*context));

    if (context == NULL) {
        aloge("fatal error! allocate IP camera context failed");
        return NULL;
    }

    return context;
}
```

使用 `calloc()` 可以在分配内存的同时把结构体清零，避免新增字段后出现未初始化值。

### 5.2 销毁上下文

```c
void destructIpCameraContext(IpCameraContext *context)
{
    free(context);
}
```

`free(NULL)` 是安全操作，因此 `cleanup` 路径可以无条件调用析构函数。

## 6 MPP 平台初始化

MPP 初始化由 `platform_init()` 完成。

### 6.1 设置系统配置

```c
MPP_SYS_CONF_S sys_conf;

memset(&sys_conf, 0, sizeof(sys_conf));
sys_conf.nAlignWidth = 32;

AW_MPI_SYS_SetConf(&sys_conf);
```

`nAlignWidth` 设置为 32，供后续媒体缓冲区和图像数据按照硬件要求对齐。

### 6.2 初始化 MPP

```c
AW_MPI_SYS_Init();
```

该接口会初始化 MPP 基础模块。开发板日志表明，调用过程中同时完成了 ISP、硬件显示基础层和 ALSA Mixer 的初始化。

### 6.3 初始化 PTS 基准

```c
uint64_t current_pts = 0;

AW_MPI_SYS_GetCurPts(&current_pts);
AW_MPI_SYS_InitPtsBase(current_pts);
```

`AW_MPI_SYS_GetCurPts()` 要求传入 `uint64_t *`，因此必须使用 `&current_pts`。PTS 基准将供后续视频、音频、编码、推流和录像模块使用。

### 6.4 错误回滚

每个 MPP 接口都检查返回值。如果 MPP 已经初始化，但 PTS 获取或 PTS 基准设置失败，`platform_init()` 会调用 `AW_MPI_SYS_Exit()` 回滚已经初始化的资源。

### 6.5 平台退出

```c
int platform_deinit(void)
{
    ERRORTYPE result = AW_MPI_SYS_Exit();
    return result == SUCCESS ? 0 : -1;
}
```

开发板日志中的 `alsaCloseMixer`、`hwd_exit` 和 `MonitorEnvVar thread will exit` 都属于 MPP 正常退出过程。

## 7 信号处理

### 7.1 支持的信号

程序处理以下两个退出信号：

| 信号 | 常见来源 | 作用 |
|---|---|---|
| `SIGINT` | 终端按下 `Ctrl+C` | 交互式停止程序 |
| `SIGTERM` | `kill` 或服务管理器 | 请求程序正常退出 |

### 7.2 信号标志

```c
static volatile sig_atomic_t g_exit_signal;
```

`sig_atomic_t` 用于保存可以在信号处理函数和主流程之间安全读写的简单标志。`volatile` 要求编译器每次都从内存读取该值，不能把它长期缓存到寄存器中。

### 7.3 信号处理函数

```c
static void handle_exit_signal(int signal_number)
{
    g_exit_signal = signal_number;
}
```

信号处理函数只记录信号编号，不执行以下操作：

- 不打印日志。
- 不调用 `free()`。
- 不调用 MPP 接口。
- 不执行互斥锁操作。

这些操作不适合在异步信号上下文中执行。真正的资源释放由主线程完成。

### 7.4 使用 sigaction 注册

```c
struct sigaction action;

memset(&action, 0, sizeof(action));
action.sa_handler = handle_exit_signal;
sigemptyset(&action.sa_mask);

sigaction(SIGINT, &action, NULL);
sigaction(SIGTERM, &action, NULL);
```

源码在包含系统头文件之前定义：

```c
#define _POSIX_C_SOURCE 200809L
```

该宏使严格 C 标准模式下能够获得 `struct sigaction`、`sigaction()` 和 `sigemptyset()` 的 POSIX 声明。

## 8 主循环

MPP 初始化成功后，程序进入主循环：

```c
alogd("[Main] Application is running; press Ctrl+C to exit");

while (g_exit_signal == 0) {
    sleep(1);
}

alogd("[Main] Exit signal received: %d", (int)g_exit_signal);
```

程序每秒检查一次退出标志。收到信号时，`sleep()` 会提前返回，循环条件随即变为假，程序进入统一清理流程。

当前主循环只负责等待退出。后续加入视频采集、推流、录像和 AI 线程后，主循环仍保留为应用生命周期的控制中心。

## 9 开发板验证

### 9.1 测试命令

```sh
./sample_strip
```

### 9.2 启动结果

开发板运行日志确认以下步骤成功：

1. glog 正常输出文件名、行号和函数名。
2. `AW_MPI_SYS_SetConf()` 执行成功。
3. MPP Platform V1.0 初始化成功。
4. ISP600 初始化成功。
5. 硬件显示基础层初始化成功。
6. 两个 ALSA Mixer 打开成功。
7. 当前 PTS 获取成功，示例值为 `10397696349 us`。
8. 程序进入持续运行状态。

关键日志：

```text
[Main] Application is running; press Ctrl+C to exit
```

### 9.3 Ctrl+C 退出结果

按下 `Ctrl+C` 后，程序记录：

```text
[Main] Exit signal received: 2
```

信号编号 2 对应 `SIGINT`。随后程序完成以下清理：

1. 关闭两个 ALSA Mixer。
2. 退出硬件显示基础层。
3. 等待 MPP `MonitorEnvVarThread` 退出。
4. 销毁应用上下文。
5. 输出最终退出日志。
6. 以返回码 0 结束。

最终日志：

```text
[Main] Application exited with code: 0
```

MPP 内部监控线程约延迟半秒退出属于正常现象。

## 10 当前阶段边界

当前版本尚未创建实际媒体通道，因此暂不具备以下功能：

- MIPI CSI 摄像头采集。
- VI 视频帧获取。
- VO 实时显示。
- G2D 旋转和格式转换。
- H.264 或 H.265 编码。
- 音频采集和 AAC 编码。
- RTSP 推流。
- MP4 录像和循环覆盖。
- OSD 时间水印。
- YOLOv8 人形检测、区域入侵和越线检测。

本阶段的作用是建立一条已经在目标板验证的稳定启动、运行和退出路径。

## 11 下一阶段计划

下一阶段实现 MIPI CSI 摄像头到 VI 的视频采集链路。

计划任务：

1. 在 `IpCameraContext` 中加入 `VIConfig` 和初始化状态。
2. 创建 `video_capture.h` 和 `video_capture.c`。
3. 配置 `VI_DEV`、`VI_CHN`、ISP 设备、分辨率、帧率和像素格式。
4. 创建并启用 VI 设备和虚拟通道。
5. 使用 `AW_MPI_VI_GetFrame()` 获取视频帧。
6. 使用 `AW_MPI_VI_ReleaseFrame()` 归还视频帧。
7. 实现失败回滚和反向释放流程。
8. 在开发板记录连续取帧数量、帧尺寸和 PTS。

完成标准：程序可以连续取得摄像头视频帧，按 `Ctrl+C` 后能够停止并销毁 VI 通道，最终以返回码 0 退出。
