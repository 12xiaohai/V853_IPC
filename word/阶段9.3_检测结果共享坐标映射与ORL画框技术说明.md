# 阶段9.3：检测结果共享、坐标映射与ORL画框

## 1. 阶段目标

阶段9.2已经能在独立VIPP 8上完成320x320 NV12实时人形检测，但检测结果只在日志中可见。本阶段完成以下工作：

1. 从NPU线程安全获取最新检测快照；
2. 把320x320模型坐标映射到1920x1080编码画面；
3. 处理NPU通路的180度方向校正；
4. 沿用原项目MPP `ORL_RGN`方式绘制人形矩形框；
5. 无目标时立即清框，NPU长时间无新结果时超时清框；
6. 不阻塞NPU推理线程，不破坏时间OSD、RTSP和MP4录像。

## 2. 为什么选择MPP ORL

原项目的`paint_objects()`并不会在CPU上逐像素修改NV21/NV12画面，而是：

1. 创建`ORL_RGN`区域；
2. 设置矩形位置、颜色、线宽和图层；
3. 把region附着到指定VIPP；
4. 由MPP硬件在通路内完成叠加。

本阶段沿用该方案，主要优点是：

- 不需要频繁复制1920x1080大尺寸图像；
- 画框不占用大量CPU时间；
- 附着到VIPP 0后，检测框会直接进入H.264编码结果；
- RTSP和MP4复用同一路H.264，因此会同时看到检测框。

## 3. 模块关系

```text
VIPP 8 (320x320 NV12)
        |
        v
   NPU推理线程
        |
        | 发布NpuDetectionSnapshot（互斥量保护）
        v
 detection_overlay线程
        |
        | 坐标反变换 + 缩放 + 2像素对齐
        v
MPP ORL_RGN ---> VIPP 0 (1920x1080) ---> VENC 0
                                           |-- H.264裸流
                                           |-- RTSP
                                           `-- MP4
```

NPU线程只负责发布快照，画框线程通过`npu_detector_get_latest()`拷贝数据。两者不共享可变指针，也不会在推理期间调用RGN接口。

## 4. 坐标映射

### 4.1 基本缩放

YOLOv8输出坐标域为320x320，编码画面为1920x1080。不考虑方向时：

```text
video_x = model_x * 1920 / 320
video_y = model_y * 1080 / 320
```

X和Y必须分别使用宽度和高度缩放比，不能共用一个比例。

### 4.2 180度方向反变换

VIPP 8实测图像倒置，因此NPU通路已同时开启`mirror=1`和`flip=1`，等效于旋转180度。NPU输出的检测坐标属于“校正后的正立画面”，而VIPP 0仍为原始方向。

因此在缩放前先执行：

```text
new_xmin = model_width  - old_xmax
new_xmax = model_width  - old_xmin
new_ymin = model_height - old_ymax
new_ymax = model_height - old_ymin
```

如果忽略这一步，检测框会出现在人物的对角位置。

### 4.3 边界与对齐

映射后还会执行：

- 坐标限制在画面边界内；
- 左上角向下取2像素对齐；
- 右下角向上取2像素对齐；
- 矩形宽高至少为2像素。

这可避免MPP因越界或非法对齐拒绝附着region。

## 5. RGN资源与OSD共存

| 用途 | 附着目标 | RGN句柄 |
|---|---|---:|
| 时间OSD | VENC 0 | 0 |
| 人形检测框 | VIPP 0 | 100～115 |

检测框和时间OSD使用不同句柄范围，而且附着层级不同，因此可以共存。当一个新快照到来时，程序按以下顺序刷新：

1. `AW_MPI_RGN_DetachFromChn`拆除旧框；
2. `AW_MPI_RGN_Destroy`销毁旧region；
3. `AW_MPI_RGN_Create`创建新ORL region；
4. `AW_MPI_RGN_AttachToChn`附着新矩形。

这一顺序与原项目一致。当前最多绘制16个人形框，避免异常结果无限占用region资源。

## 6. 过期框清理

画框线程每50 ms读取一次快照：

- `sequence`变化：立即刷新框；
- 新快照的`detection_count=0`：立即清除旧框；
- 500 ms没有任何新快照：判定NPU结果过期并清框。

超时使用`CLOCK_MONOTONIC`，不会受开发板NTP校时影响。

## 7. 启停顺序

启动顺序：

```text
VIPP 0 / VENC -> NPU detector -> detection overlay
```

停止顺序：

```text
detection overlay -> NPU detector -> VENC
```

画框模块同时依赖NPU快照和VIPP 0，因此必须第一个停止。它在退出时会拆除所有region，防止下次启动遇到句柄冲突。

2. 人走入画面，确认黄色矩形框跟随人物；

## 11. 本阶段可能遇到的问题

### 11.1 有检测日志，但RTSP中没有框

优先查看是否有`Create region failed`或`Attach region failed`。检查目标是否为`VIPP0:0`，以及RGN句柄100～115是否被其他模块占用。

### 11.2 框在人物的对角

说明NPU画面和编码画面方向不一致。当前配置使用`map_mirror=1`和`map_flip=1`执行180度反变换。如果后续也把VIPP 0配置为正立输出，这两项应同步改为0。

### 11.3 框停在旧位置

检查NPU的`sequence`是否继续增加。若NPU无新快照，程序应在500 ms后输出`Stale detection boxes cleared`并清框。

### 11.4 频繁报region句柄已存在

检查退出顺序，必须在销毁VIPP 0之前执行`detection_overlay_stop()`。正常停止会先Detach再Destroy所有活动句柄。
