# 阶段9.1：YOLOv8 NPU环境与单帧推理技术说明

## 1. 阶段目标

本阶段先把YOLOv8推理从摄像头、显示、编码、RTSP和录像链路中隔离出来，验证：

1. V853的VIPLite/NPU驱动能够正常初始化；
2. AWNN能够读取并创建`yolov8n.nb`网络；
3. 网络能够接收一帧`320x320 NV21`图像并完成推理；
4. 程序能够解析YOLOv8输出张量；
5. 能够筛选COCO类别0（person）并执行NMS；
6. 退出时网络、NPU内存和输入缓冲均正常释放。

独立验证通过后，阶段9.2再创建NPU专用VI通路并接入实时视频帧。这样出现问题
时可以明确区分“模型/NPU/后处理问题”和“实时视频输入问题”。

## 2. 为什么切换到YOLOv8

原项目同时保存了两套检测实现：

- `1.1.0_Beta.nb`配合`AWNN_DET_POST_HUMANOID_1`的人形模型；
- `yolov8n.nb`配合自定义张量解码和NMS的通用目标模型。

原配置文件中的`nn_type=0`默认启用第一套，但项目代码已经包含YOLOv8网络及
后处理。为了让本复刻项目和简历中的“基于YOLOv8的人形检测”完全一致，阶段
9.1从现在起使用第二套，并只保留YOLOv8输出中的`person`类别。

默认模型路径为：

```text
/lib/yolov8n.nb
```

仓库内模型保存在：

```text
models/yolov8n.nb
```

执行`./build.sh firmware`时，固件脚本会自动将它安装到`/lib/yolov8n.nb`。

## 3. NPU推理流程

```text
awnn_get_info(yolov8n.nb)
    -> 校验模型输入为320x320
    -> awnn_init(model_mem_size)
    -> awnn_create
    -> awnn_set_input_buffers(Y, VU)
    -> awnn_run
    -> awnn_get_output_buffers
    -> YOLOv8张量解析
    -> person筛选
    -> NMS
    -> awnn_destroy
    -> awnn_uninit
```

阶段9.1只运行一帧，不创建实时检测线程，也不会启动摄像头、LCD、编码、RTSP、
音频或录像服务。

## 4. 输入图像

YOLOv8模型输入为`320x320 NV21`：

```text
Y平面：  320 x 320 = 102400字节
VU平面： 320 x 160 =  51200字节
总大小：                 153600字节
```

320已经满足32像素对齐，因此紧凑高度和NPU对齐高度相同。没有传入图片时，
程序生成`Y=16、VU=128`的黑色NV21帧，只验证模型和NPU能否运行；黑帧没有
检测结果属于正常现象。

## 5. YOLOv8输出与后处理

原项目的`yolov8n.nb`固定输出：

```text
[1, 84, 2100]
```

其中：

- 前4个属性是`center_x、center_y、width、height`；
- 后80个属性是COCO类别概率；
- 2100个候选来自`40x40 + 20x20 + 10x10`三层特征图；
- COCO类别0为`person`。

本阶段后处理不依赖OpenCV：

1. 直接按NCW布局访问输出，避免额外转置大数组；
2. 为每个候选找出80类中的最大概率类别；
3. 只保留最大类别为person且置信度大于0.25的候选；
4. 把中心点形式转换为左上角、右下角坐标；
5. 将坐标限制在`320x320`范围内；
6. 按置信度排序并以IoU 0.45执行NMS；
7. 最多输出100个人形框。

该模块位于：

```text
sample/ipc_camera/app/yolov8_postprocess.c
sample/ipc_camera/include/yolov8_postprocess.h
```

后续实时检测、区域入侵和越线判断会直接复用它。

## 6. 开发板验证

### 6.1 准备模型

如果当前固件已经包含模型：

```sh
ls -lh /lib/yolov8n.nb
```

如果不存在，将仓库中的`models/yolov8n.nb`复制到UDISK，然后直接使用UDISK
路径，不必写入只读rootfs：

```sh
ls -lh /mnt/UDISK/yolov8n.nb
```

### 6.2 黑帧基础自检

模型位于`/lib`时：

```sh
./sample_strip --npu-self-test
```

模型位于UDISK时：

```sh
./sample_strip --npu-self-test /mnt/UDISK/yolov8n.nb
```

预期关键日志：

```text
[Main] Running Stage 9.1 NPU single-frame self-test
[NPU] Model: ..., visible=320x320, tensor=320x320, ...
[NPU] No input file supplied; using a black NV21 frame
[NPU] Single-frame inference succeeded: cost=... us, objects=0,
      threshold=0.250
[Main] Application exited with code: 0
```

### 6.3 真实人形图片

将之前保存的1920x1080 NV21帧转换为模型输入：

```sh
ffmpeg -f rawvideo -pixel_format nv21 -video_size 1920x1080 \
    -i preview_frame_1920x1080.nv21 \
    -vf scale=320:320 -frames:v 1 -pix_fmt nv21 -f rawvideo \
    npu_test_320x320.nv21
```

把模型和测试图片复制到开发板后执行：

```sh
./sample_strip --npu-self-test \
    /mnt/UDISK/yolov8n.nb \
    /mnt/UDISK/npu_test_320x320.nv21
```

含人的输入应至少出现一个：

```text
[NPU] Result[0]: label=0, score=..., box=(xmin,ymin)-(xmax,ymax)
```

`objects=0`不等于NPU执行失败，它只表示当前图片中没有超过阈值的人形目标。
是否运行成功应以`Single-frame inference succeeded`和退出码0为准。

## 7. 安全设计

- 模型输入必须严格为`320x320`；
- 模型内存需求不能为0；
- 输入文件必须严格为153600字节；
- 所有张量值在使用前检查是否为有限浮点数；
- 无效或越界检测框会被丢弃；
- 使用`CLOCK_MONOTONIC`统计推理时间，避免NTP校时干扰；
- 任一阶段失败都进入统一清理路径；
- 只有网络创建成功后才销毁网络；
- 只有AWNN初始化后才执行反初始化。

这证明板端NPU驱动和AWNN运行环境可用。该结果不能替代YOLOv8模型验证，当前
仍需重新编译程序并使用`yolov8n.nb`执行第6节的两项测试。
